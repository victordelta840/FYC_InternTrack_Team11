## 3. Setup — the exact commands you'll run

### Prerequisites
- Node.js 20 LTS
- XAMPP with MySQL 8.0+ (Apache/PHP not required)
- npm (bundled with Node)

### Step 1 — Start MySQL from XAMPP
Open XAMPP Control Panel → click **Start** next to MySQL. Default port `3306`, empty root password.

### Step 2 — Create the database
Open phpMyAdmin (or `mysql -u root`) and run:
```sql
CREATE DATABASE interntrack_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### Step 3 — Backend
```bash
cd interntrack-enterprise/backend
cp .env.example .env
# open .env and confirm DB_HOST=127.0.0.1, DB_PORT=3306, DB_USERNAME=root, DB_PASSWORD=(blank), DB_DATABASE=interntrack_db
npm install
npm run keys:generate       # writes keys/jwt-private.pem + keys/jwt-public.pem
npm run migration:run       # creates 13 tables in interntrack_db
npm run seed                # inserts 4 users + 1 internship + 40 attendance days
npm run start:dev           # starts NestJS on http://localhost:4000
```

### Step 4 — Frontend (in a separate terminal)
```bash
cd interntrack-enterprise/frontend
cp .env.example .env.local
npm install
npm run dev                 # starts Next.js on http://localhost:3001
```

### Step 5 — Open the app
- Portal (student/mentor): **http://localhost:3001/auth/login**
- Admin gateway (isolated): **http://localhost:3001/admin/login**
- Backend health check: **http://localhost:4000/api/v1/health**

## 5. Manual verification checklist

Copy-paste this checklist while you test:

### Auth & isolation
- [ ] Admin cannot log in on `/auth/login` (should get `403 Forbidden`)
- [ ] Mentor cannot log in on `/admin/login`
- [ ] After 5 failed logins the account is locked for 15 min
- [ ] Refresh token rotates on `/auth/refresh` (check cookie in DevTools)

### Attendance engine
- [ ] Mentor marks attendance for a student → row appears in DB
- [ ] Marking twice for same day returns error code `ATTENDANCE_EXISTS`
- [ ] Editing existing day requires justification (min 5 chars); creates a row in `attendance_revisions`
- [ ] Import a CSV (use `docs/sample-attendance-import.csv`) → staging preview shows fuzzy-matched headers and per-row errors
- [ ] Commit stage inserts only valid rows in a transaction

### 90.00% Absolute Rule
- [ ] Student1 (95%) sees green "Eligible" badge and can click Generate Certificate
- [ ] Student2 (87.5%) sees "Below Threshold" with `Short by 2.50%` — button is disabled
- [ ] Direct API call `POST /certificates/self-issue` for student2 returns HTTP 400 with `code: "ATTENDANCE_BELOW_THRESHOLD"`

### Templates & Certificate
- [ ] Upload a PNG template → OCR runs locally (may take 5–30s first time)
- [ ] If OCR is inconfident, drag-drop box on canvas assigns coordinates
- [ ] Activate template (only one can be active)
- [ ] Student1 generates certificate → PDF downloads with fields painted at your coordinates

### Complaints + SLA
- [ ] Student files complaint → row inserted with `sla_breach_at = now + 48h`
- [ ] Complaint appears in Admin Kanban "OPEN" column and Mentor's queue
- [ ] Mentor transitions OPEN → RESOLVED: prompts for notes (rejects < 5 chars)
- [ ] To test SLA escalation manually, run in phpMyAdmin:
  ```sql
  UPDATE complaints SET sla_breach_at = NOW() - INTERVAL 1 HOUR WHERE status = 'OPEN';
  ```
  Wait up to 10 minutes for the cron. The complaint should auto-transition to ESCALATED and reassign to the admin.

### Webhooks
- [ ] Create a webhook pointing at `https://webhook.site/<your-uuid>`, select event `*`
- [ ] Copy the one-time secret shown in the modal
- [ ] Register a new student → check webhook.site — should see a POST with `X-Webhook-Signature: sha256=<hex>` header
- [ ] Verify HMAC:
  ```js
  const expected = crypto.createHmac('sha256', SECRET).update(`${timestamp}.${rawBody}`).digest('hex');
  ```
- [ ] Point a webhook at a bad URL (e.g. `http://localhost:9999`) → job goes to FAILED after 5 retries with exponential backoff
- [ ] Click **Retry** on the failed delivery → job returns to PENDING and is picked up on next tick

### Audit trail
- [ ] Any POST/PATCH/DELETE writes a row in `audit_logs` with user_id, action, resource, IP, and sanitized body

## 8. If you hit trouble

- **`ER_ACCESS_DENIED_ERROR`** → confirm `DB_USERNAME` / `DB_PASSWORD` in `backend/.env`
- **`ER_NOT_SUPPORTED_AUTH_MODE`** → in phpMyAdmin: `ALTER USER 'root'@'localhost' IDENTIFIED WITH mysql_native_password BY ''; FLUSH PRIVILEGES;`
- **`ECONNREFUSED 127.0.0.1:3306`** → MySQL is not running. Start it from XAMPP.
- **Frontend can't reach API** → confirm `NEXT_PUBLIC_API_URL=http://localhost:4000/api/v1` in `frontend/.env.local`
- **Certificates 500-ing during render** → an active template must exist AND its mapping must have at least one field. Visit `/admin/templates`.
- **OCR takes 20+ seconds first time** → tesseract.js downloads language data once. Subsequent uploads are fast.
